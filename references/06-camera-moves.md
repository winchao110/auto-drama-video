# 06 · 运镜目录与选用方法（H3）

写给"要写 H3 分段提示词的那个人"（也就是你，AI）。

- **数据源**：`references/camera-moves.json`（44 条，唯一事实源；脚本与工作台页面都读它，别在这里另抄一份改）。
- **目标**：让每一段的运镜是**为这场戏服务的**，不是为了炫技。没有一个镜头是"随机"的。
- **不强制**：大部分 shot 用最朴素的方式拍（固定机位 / 过肩 / 中景）。整段没有运镜也是合格答案。

---

## 一、三个必须先想清楚的问题

写每一段之前，先回答这三个问题，答案决定要不要运镜、用哪个：

1. **这场戏的"戏眼"是什么？**——观众必须在哪一秒知道什么事？（她知道他在说谎 / 他没救了 / 他们完了）
2. **这一秒要让观众"站在谁的位置"？**——在他身后看（过肩）、在他眼睛里看（POV）、在上帝的位置看（俯拍/环绕）、在角落偷看（遮挡）。
3. **这一段的"能量走向"是收还是放？**——收（推近、压下来、变窄）还是放（拉开、升高、露出更大的世界）。

> 戏眼 + 站位 + 能量走向 → 运镜。**不是先选运镜，再给它找理由。**

## 二、全球一线导演的六个选用习惯（照这个顺序想）

这些是行业里顶级导演在分镜阶段的真实取舍逻辑，直接当思考顺序用：

| # | 习惯 | 具体做法 | 落到提示词 |
|---|---|---|---|
| 1 | **先删，再加** | 一场戏里最先砍掉的永远是运镜。默认定机位能演完的，就不动。 | 一段 3–4 个 shot，**最多 1 个 shot 有明确运镜**，其余固定或极轻（微推/微移） |
| 2 | **运镜必须换个信息** | 摄影机一动，观众就expecting新信息。动了却没给新东西 = 空洞。 | 每个运镜 shot 都要能回答"它多给了观众什么"（角度、空间、关系、时间感） |
| 3 | **能量跟着戏走** | 戏在升 → 镜头收（推、压、变窄）；戏在落/收尾 → 镜头放（拉、升、露空间）。**反着来才有力**：最痛的一句台词配拉远，人更孤独。 | 结尾段用 B2 拉 / E6 俯 / A4 变焦拉；对峙升温用 B1 推 / G6 过肩推 |
| 4 | **一种"在场感"贯穿全场** | 手持 / 斯坦尼康 / 三脚架 是三种世界观，同一场戏里不许混。 | 一场戏内 `F1/F2`（手持系）与 `F3/F4`（稳定系）**二选一** |
| 5 | **越贵越省** | 摇臂、360 环绕、子弹时间、希区柯克变焦是"大牌"，全片给 1–2 次，给最重的那场。 | `B8 / C2 / C3 / D1 / D2 / C5 / D4` 全片各 ≤1 次；`C2` 与 `C3` 不同时出现在同一部剧 |
| 6 | **接点比单镜重要** | 观众记住的是"两个镜头之间"。切点上的景别/方向跳变，比单个镜头漂亮更影响观感。 | 见第四节「跨段防闪」——这是硬规则，不是建议 |

**一句话**：镜头动，是因为**人物心里的东西动了**；人物没动，镜头就别动。

## 三、档位 T0 / T1 / T2（决定挂不挂 LoRA）

用户钦定的分档，`check` 会按这个判。

| 档位 | 什么情况 | 生成时怎么处理 |
|---|---|---|
| **T0** | **近景**（`size: near`）的运镜。近景是表演的主战场，运镜质量直接影响脸。 | 需要 LoRA 就用（本机有必挂）；`strength` 按目录值 |
| **T1** | **中景 / 全景**（`size: mid` / `wide`）。包含两种情况：<br>① 这个运镜**本来就不需要 LoRA**（`need: native`）<br>② 需要 LoRA，且**本机存在**这个文件 | ① 不挂，纯提示词写清楚运镜<br>② 挂上，并前置触发词 |
| **T2** | 需要 LoRA，但**本机没有**这个文件（或只有文件名对不上） | **不挂 LoRA，也不写触发词**，改用目录里的 `fallback` 降级句（若无 fallback 就用 `sentence` 正常写，靠模型自身能力） |

**硬规则**

- **每段视频最多 1 个运镜 LoRA**。它挂在独立的 `491` 节点，**不占**工作台上那三个可选 LoRA 位（`53` / `400` / `490`）。
- 一段里若有两个 shot 都想用带 LoRA 的运镜 → **留戏更重的那个**，另一个换同功能的 `native` 运镜（例：`C2 全环绕` → `C1 半环绕`）。
- 目录里 `need: lora` 的运镜一共 8 条：`E1 / F3 / F4 / C2 / C3 / D4 / D1 / D2`。其余 36 条**天生不用 LoRA**，不占名额。
- **可用性由机器判**，不要凭空假设本机有：`drama.py videos` 会实时读 ComfyUI 的 LoRA 列表，按 **basename**（不含子目录）小写比对；
  主名对不上时用 `aliases` 做**同功能替代**匹配（例：`C2/C3` 的 `flf2v` 找不到，但有 `minimax_h3_orb360_*` → 视为有）。
- 匹配不到 → 自动降 T2，不报错、不断流程。

**为什么要 basename 比对**：ComfyUI 返回的是 `MiniMaxH3\dolly_zoom_minimaxh3_v1.safetensors` 这种带子目录的路径，
而你把文件放在哪个子目录是随意的。所以只看文件名。

## 四、跨段接头：首尾镜头不许同机位（硬规则）

**用户原话**：

> 比如第一段最后一个 shot A 角色在说话或者行动，他的剧情没完，在下一段第一个 shot 还是 A 角色在说话或行动，
> 这种情况，下一段的第一个 shot 不要跟上一段的最后一个 shot 相同的镜头，如果是相同的镜头，拼接后会有闪烁或人物跳动。

**原因**：H3 是分段独立生成的，两段的最后一帧和第一帧**永远不可能像素级一致**。如果两段都是"同一个景别、同一个机位方向",
观众的视觉系统会把这点差异读到，于是看到：**闪一下 / 人物跳一下 / 衣服褶皱变了 / 背景挪了**。
只要换机位（景别变 or 方向变），这点差异就被**剪辑点的合法性**掩盖掉了 —— 这就是电影的"跳切保护"。

**做法**（写 `[Shot N]` 时就要规划，不是事后抢救）：

| 上一段尾镜 | 下一段首镜 | 处理 |
|---|---|---|
| 中景 · 略偏左 | 中景 · 略偏左 | ❌ 硬问题 → 换方向（改从右侧过肩）或换景别（收到近景 / 拉开到全景） |
| 过肩（A 背对） | 过肩（A 背对） | ❌ 硬问题 → 下一段改成正打 A 的脸，或反打 B |
| 近景 · 正面 | 近景 · 正面 | ❌ 硬问题 → 换成侧面 / 过肩 / 手部特写 / 空镜过渡 |
| 全景 · 正面 | 中景 · 侧面 | ✅ 景别和方向都变了 |
| 中景 · 正面 | 近景 · 正面 | ✅ 景别变了就够（同方向不违规） |
| 中景 · 正面 | 中景 · 侧面 | ✅ 方向变了就够（同景别不违规） |

**首选解法，按优先级**：
1. **换景别**（中景 → 近景）：最自然，且不需要改戏。
2. **换方向**（正面 → 侧面 / 过肩）：适合对话接力。
3. **插一个过渡镜**：空镜、道具特写、环境镜（0.5–1s 就够），把接点挪走。
4. **换人物**：如果 B 在场，下一段首镜直接给 B 的反应，A 的话用画外音接。

> `check` 会自动抓这个：解析每段 `[Shot N]` 的**景别词 + 机位方向词**指纹，相邻两段"尾镜 vs 首镜"同景别**且**同方向 → 报硬问题。

## 六、怎么把它写进 drama.json

### 6.1 字段

运镜挂在**段**上（不是 shot 上，因为一张卡一个 video）：

```json
{
  "id": "P03",
  "sec": 6,
  "camera": { "move": "B1", "why": "她说完那句谎，他意识到被骗——推近，把观众按到他脸上" },
  "prompt": { "en": "...", "zh": "..." }
}
```

- `move`：目录里的 `id`。**空字符串 = 这段不用运镜**（完全合法，也是最常见的选择）。
- `why`：**一句戏因**。写不出戏因就别用这个运镜。`check` 会检查它是否为空。
- 一段只能有**一个** `move`（因为一段最多挂一个运镜 LoRA）。

### 6.2 写提示词的顺序

1. 先按 `01-h3-prompt-bilingual.md` 把这段拆成 `[Shot 1] [Shot 2] …`，每 shot 写清景别 + 站位 + 前景后景 + 动作。
2. 决定哪个 shot 承载运镜（**其余 shot 保持固定或极轻**）。
3. 把目录里 `sentence.zh` / `sentence.en` **融合进那个 shot 的句子中**（不是另起一行贴上去）：
   - ✅ `[Shot 2] 起手中景（腰部以上）；机位以慢速前移推近至头部与肩部特写；焦距不变。他喉结动了一下，视线落向桌面。`
   - ❌ `[Shot 2] 中景。他低头。` 然后单独一行 `运镜：推镜头。`
4. **T2**（要 LoRA 但本机没有）→ 用 `fallback`（若无则用 `sentence`），并把表现预期写低一点（别要求"主体大小不变、背景透视炸开"这种只有 LoRA 才做得到的精度）。
5. **T1 且本机有 LoRA** → `videos` 会自动把 `trigger` 前置到整段提示词最前面，**你不需要手动写触发词**；但正文里仍要写清运镜本身（LoRA 是加强，不是替代描述）。

### 6.3 一段 3–4 个 shot 的典型排布

| shot | 景别 | 运镜 | 说明 |
|---|---|---|---|
| Shot 1 | 中景 / 全景 | 定机位（可选 `F8` 穿越入场） | 交代空间与站位 |
| Shot 2 | 近景 | `B1` 推 / `D5` 移焦 / `D1` 希区柯克 | **戏眼所在，唯一运镜位** |
| Shot 3 | 近景 / 特写 | 定机位 | 反应，让观众喘一口气 |
| Shot 4（可选） | 全景 | `B2` 拉 / `A4` 变焦拉 | 收尾抽离 |

## 七、常见错误

| 错误 | 为什么不行 | 改成 |
|---|---|---|
| 一段里 3 个 shot 全在动 | 观众画面一直在漂，看不到表演 | 只留 1 个，其余定机位 |
| 每个 shot 都想用 `C2 全环绕` | 大牌镜头用滥，戏就不重了 | 全片 ≤1 次，给最重那场 |
| `D1` 希区柯克配中景 | 希区柯克变焦靠"主体大小不变"制造心理地震，中景以上脸糊就废了 | 必须近景，`size` 已是 `near` |
| 上一段尾镜是过肩、下一段首镜还是同方向过肩 | 拼接会闪、人物会跳 | 见第四节，换景别或换方向 |
| 用了 T2 运镜却在提示词里写"主体大小绝对不变" | H3 原生能力做不到，白写还占字数 | 降级描述："机位前移，背景略微拉开" |
| 同一场戏前一段手持、后一段斯坦尼康 | 两种世界观看得出来 | 全场统一"在场感" |
| `camera.why` 空着 | 说明这个运镜没理由，纯装饰 | 删掉运镜，或补一句戏因 |

## 八、自检清单（写完一段过一遍）

- [ ] 这段的戏眼是哪一秒？运镜是否就落在那一秒？
- [ ] 这个运镜**多给了观众什么**？（角度 / 空间 / 关系 / 时间感，至少一个）
- [ ] 整段只有 1 个运镜 shot 吗？其他 shot 是否定机位？
- [ ] 带 LoRA 的运镜全段是否 ≤1 个？是否与三个可选 LoRA 位的意图不冲突？
- [ ] 本机有没有这个 LoRA？（拿不准就交给脚本判，别硬写）
- [ ] 上一段的**最后一个 shot** 与本段**第一个 shot**，景别或方向是否不同？（防闪/防跳）
- [ ] `camera.why` 写了吗？写得出一句人话吗？
